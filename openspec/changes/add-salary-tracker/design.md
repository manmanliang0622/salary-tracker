# Design

## Context

全新專案，沒有既有程式碼。動機見 proposal.md。成品要在 claude.ai Artifact 環境執行：只能載入白名單 CDN 的 script 與 Google Fonts，不能用 `alert/confirm/prompt`，資料要靠平台的 `db` capability 保存。使用者以手機為主要裝置，並指定可愛手帳風格（參考圖：奶油色底、手繪墨線格子、小動物插圖、鯛魚燒）。

## Goals / Non-Goals

**Goals:**
- 單一 HTML 檔即可發佈，開啟即可用，手機與桌機都好操作。
- 計算邏輯集中在純函式，方便用範例資料驗證。
- 雲端資料只屬於使用者本人。

**Non-Goals:**
- 加班費分段（1.34 / 1.67 倍）、所得稅、勞退自提、其他加給或扣款。
- 週結、半月結的計薪週期。
- 匯出 Excel / PDF。

## Decisions

### 1. 單一 HTML、原生 JS
畫面只有四個分頁與兩種底部面板，用字串模板 + 事件委派即可。React 等框架只會增加載入時間。
- 替代方案：React UMD — 對這個規模沒有好處。

### 2. 資料模型：每月一份排班文件
路徑都在 `data/users/<uid>/` 之下（平台保證私有）：
- `data/users/<uid>/settings` — 費率設定（一份文件）
- `data/users/<uid>/profile/jobs/<jobId>` — 每份工作一份文件
- `data/users/<uid>/profile/months/<YYYY-MM>` — 每月一份：`{days: {日期: {jobId: {h, m?}}}, dbl: {日期: true}, note: {日期: 文字}}`

每月一份而不是每班一份：文件數少（一年 12 份），一次訂閱就能拿到全部；單月資料遠小於 256 KiB 上限。`m` 只在使用者手動切換單班倍率時才存，未設定時跟隨 `dbl`。
- 替代方案：每班一份文件 — 文件數會隨時間無上限成長。

### 3. 寫入策略
本地狀態為主，修改後 600ms 去抖動，再依月份逐一 `set` 整份月文件；同一份文件一次只寫一筆。訂閱回來的快照，若該月份還有未寫出或寫入中的修改就忽略，避免蓋掉使用者正在輸入的內容。

### 4. 計薪區間與發薪日的計算
以 (年, 月, 日) 整數運算，不依賴時區：
- 起始日 1：區間為該月 1 日到月底。
- 起始日 N：日期 ≥ N 時區間為本月 N 日到下月 N−1 日，否則為上月 N 日到本月 N−1 日。
- 區間以「結束月份」為鍵；發薪日 = 結束月份 + 位移月份的第 D 日（不超過該月天數）。

### 5. 勞健保級距
內建 2026 年表（基本工資 29,500）：勞保含部分工時低級距 11,100～28,800，一般級距 29,500～45,800；健保 29,500 起。費率存在使用者設定中可修改，以因應往後調整。「自動」模式依當期毛額對應級距。實際投保薪資是加保時申報的固定值，所以介面註明「依實際薪資單為準」。

### 6. 視覺
- 色彩 token：紙張奶油底、可可棕墨線、鯛魚燒金黃強調色，六種粉彩作為工作顏色（存 `p1`～`p6` 代號，深色模式自動換成低亮度版本）。
- 字體：標題與金額用 LXGW WenKai TC（手寫楷書感），內文 Noto Sans TC。
- 元件：1.6px 墨線、不等圓角、2px 位移硬陰影，像貼紙；插圖（貓咪抱錢袋、小狗、鯛魚燒）全部是 inline SVG `<symbol>`；背景有淡淡腳印紋。
- 版面：手機優先單欄，最大寬度 720px，底部固定分頁列（首頁／月曆／工作／統計）。

## Risks / Trade-offs

- [級距表或費率過時] → 費率可在統計頁修改；級距可改為固定並自選；文件標註需每年檢查。
- [自動級距與實際申報不同] → 提供固定級距選項，畫面註明以薪資單為準。
- [兩台裝置同時編輯同一個月] → 最後寫入者為準；個人使用情境下可接受。
- [刪除工作後舊排班仍留在月文件] → 計算時忽略不存在的工作；資料量很小，不另外清理。

## Migration Plan

全新功能，無需搬移。發佈為 Artifact；回滾方式是重新發佈前一版 HTML。
